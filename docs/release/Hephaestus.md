# Hephaestus

Hephaestus 是一个面向个人使用的 AI Agent 平台。它把持续对话、身份切换、项目文件、工具调用、自动化工作流和定时任务放在同一个可维护的运行环境中。

它服务于需要长期使用、需要保留上下文与工作痕迹、并希望按自己的方式组合 Agent 能力的开发者。平台强调配置可读、运行可追溯，以及在聊天和自动化之间保持清晰边界。

## 使用方式

平台提供网页接口和 HTTP API。网页用于日常对话、管理会话、项目和配置；API 可用于接入其他客户端或自动化调用。运行中的工作流和聊天都可以通过流式事件反馈文本、推理片段、工具调用和执行结果。

Hephaestus 默认适合运行在个人电脑或受信任网络中。它不提供内置的多用户认证或权限隔离；当启用本地 Shell、文件访问或网络工具时，应继续保持本地绑定或在外部反向代理中补充访问控制。

## 核心概念

### Identity

Identity 定义 Agent 的核心行为与模型偏好，包括系统提示词、注入消息、模型选择、思考强度和常用生成参数。它是可复用的静态配置，不包含某次对话的上下文。

不同 Identity 可以服务于不同场景，例如陪伴式聊天、编程协作、信息整理或特定领域任务。会话可以在运行过程中切换 Identity；切换只影响之后的调用，不会改写已有历史。

### Impression

Impression 是一组按顺序附加到 Agent 上下文的消息。它适合表达长期的角色背景、工作原则、场景约束或用户偏好。每个 Impression 可以独立启用或停用，并可在会话中动态调整。

### Tool Group

Tool Group 把平台内置工具组合成可管理的能力集。会话选择的是工具组，而不是任意单个工具，因此可以用较少的配置控制一类能力何时对 Agent 开放。

### Concierge

Concierge 是创建聊天体验和执行自动化的起点。它组合一个 Identity、若干 Impression、Tool Group 和 Plugin，并保持这些列表的顺序。创建会话时，Concierge 的当前设置会成为该会话的初始设置；之后会话可独立调整，不会反向修改 Concierge。

### Project

Project 是带有独立工作目录的工作空间。会话、文件上传和可用 Concierge 都可以关联到 Project。平台会为 Project 准备基础说明文件，Agent 也可以在用户明确允许的情况下创建新 Project。

Project 提供的是工作上下文和文件组织边界，不是多用户安全边界。文件与 Shell 工具默认围绕当前 Project 工作；是否开放额外路径由部署者决定。

### Plugin

Plugin 是平台侧的扩展能力，对 Agent 本身不可见。它可以在用户消息进入、工具调用、上下文整理、模型调用和回复完成等阶段观察或调整会话流程。

当前内置能力包括：

- 环境上下文：为新会话补充位置、时间和天气等信息。
- 会话摘要：在成功完成的会话轮次后更新标题和摘要。
- 剧情状态：维护可供 Agent 读取的紧凑状态信息，并附加到回复中。
- 回复建议：根据最近的助手回复生成可选的下一条用户消息。

Plugin 的失败或超时不会中断正常会话；平台会跳过该次执行并记录告警。固定 Plugin 不能由单个会话停用。

## 对话与会话

### 持久会话

每个 Session 都保存自己的当前设置、关联 Project、标题、摘要和完整消息树。历史不会因为编辑、重新生成或切换分支而被覆盖。

会话保留一个当前活跃分支。客户端可以取得该会话的完整消息树，并选择任意有效分支继续对话。新的消息会从当前分支继续，避免在并发操作时悄悄覆盖另一条路径。

### 编辑、分支与继续生成

用户可以编辑已有的助手消息、从助手消息创建新会话分支，或重新生成最近的回复。重新生成会保留原回复，并产生新的候选分支。

当流式生成中断但已获得可见内容时，平台可以保留该回复并标记为未完成。用户可以从该位置继续生成，而不必丢失已产生的文本。若并发请求导致活跃分支已改变，已生成结果会保留为可访问的非活跃分支，并明确告知客户端没有自动切换过去。

### 上下文整理

平台会在会话接近模型上下文容量时整理较早的历史，保留可继续对话的压缩上下文和近期消息。压缩失败时，当前输入不会被写入会话，从而避免在不完整上下文上继续生成。

### 会话命令

以下命令在平台本地处理，不会写入聊天历史，也不会发送给模型：

- `/help`、`/ping`：查看命令帮助和平台连通性。
- `/stop`：请求终止当前会话的运行任务。
- `/status`：查看会话设置、Project、上下文估算和近期告警。
- `/list`、`/detail`：浏览身份、印象、工具组、插件、Concierge、会话、Project、Workflow 和 Job。
- `/switch`：切换 Identity、Concierge、Project 或打开另一个会话。
- `/activate`、`/deactivate`：调整当前会话启用的 Impression、Tool Group 或非固定 Plugin。
- `/clear [true|false]`：基于当前会话设置创建并切换到新会话。`archive` 默认为 `false`；传入 `true` 时归档当前会话。
- `/new [true|false]`：从当前会话的源 Concierge 创建并切换到新会话。`archive` 默认为 `false`；传入 `true` 时归档当前会话。
- `/interact approve|deny`：回应等待中的敏感操作确认。
- `/interact auto-approve`：为当前 Session 开启本次服务进程内的自动授权；若已有等待中的请求，会立即同意该请求。
- `/interact cancel-auto-approve`：关闭当前 Session 的自动授权。

## 工具与文件

平台按配置向 Agent 提供工具。现有能力覆盖：

- 在当前 Project 中搜索和读取聊天历史。
- 创建和列出 Project。
- 搜索互联网，并在可用时汇总多个来源的结果。
- 获取网页内容；可使用外部抓取服务或本地浏览器。
- 在启用后执行 Shell 命令，可选择本机或远程工作环境。
- 将 Project 中已有文件作为助手附件发送给用户。

高风险 Shell 操作会请求用户确认。网页流式对话可通过 `/interact approve|deny` 明确同意或拒绝，也可通过 `/interact auto-approve` 在当前 Session 内临时允许后续操作；自动授权不写入数据库，服务重启后会关闭。外部通道会发送确认提示，收到明确同意后继续；也可回复“全部同意”或 “approve all”开启当前会话的自动授权，回复“取消自动授权”或 “cancel automatic approval”关闭它。超时处理遵循当前部署的授权策略。

用户消息可携带多个附件。小型文本文件可直接作为提示上下文，支持的图片可在配置 OCR 后提取文本；未能提取的文件仍会保存在所属 Project 中。助手发送的文件是 Project 文件的受控引用：下载时会重新校验路径与文件状态，因此该文件之后可能更新或不再可用。

## 配置与运行时调整

Identity、Impression、Tool Group、Concierge、Workflow 和 Job 都是命名配置。平台启动时会载入配置目录中的基线内容，并将可编辑配置保存在运行时存储中。

通过配置接口更新记录时，平台会先验证所有相互引用关系；验证成功后，新的完整配置会立即用于后续对话和新运行。进行中的 Workflow 和 Job 会继续使用启动时捕获的定义，避免配置修改改变已经开始的工作。

配置文件适合维护初始基线，运行时接口适合日常增删改。删除一个与基线同名的运行时配置后，若基线仍然存在，它会在下一次启动时恢复。

## Workflow

Workflow 用自然语言步骤描述一项可重复执行的工作。每个步骤都会在指定 Project 中作为独立 Agent 轮次执行，可以使用 Concierge 提供的身份、上下文和工具。

Workflow 支持输入与输出约束。运行时会保存每一步的状态、文本、输出和执行记录；后续步骤可以使用之前步骤的结果。一个 Workflow 可以异步启动、查看进度、订阅流式事件，或在运行期间请求取消。

平台重启时，未完成的 Workflow 会被标记为中断，不会在原位置自动续跑。这样可以保留失败现场，并避免在未知外部状态下重复执行工具操作。

## Job

Job 用于在合适的时间或条件下触发一个或多个 Workflow。它可根据本机时间、最近会话活动、当日执行次数和前次成功时间等状态决定是否满足条件。

Job 在启动时检查一次，之后定期重新评估。每个 Job 会避免与自身重叠执行，并记录运行状态、失败信息、已完成的 Workflow 和每日执行情况。一个绑定 Workflow 的失败不会阻止同一 Job 后续绑定的 Workflow 尝试运行；每个绑定也可以设置自己的重试策略。

Job 与 Workflow 都支持查看历史运行记录和取消正在运行的任务。

## 外部通道

可选的 QQ 通道可以把单个外部聊天连接到持久 Session。每个外部聊天按顺序处理消息，避免同一对话中的请求相互穿插。附件会复制到绑定 Session 所属 Project，助手生成的文件也可以回传给支持文件发送的通道。

外部聊天可使用与网页相同的斜杠命令。`/new`、`/clear` 或会话切换会更新该外部聊天绑定的目标会话。删除 Session 时，其外部通道绑定会一并移除；下一条外部消息会重新建立可用会话。

## 运行可见性与恢复

平台记录工具调用、聊天消息、压缩结果、工作流步骤、任务运行和配置变更所需的运行数据。`/status` 会展示近期警告；可选的通知通道可接收运行异常和关注事件。

服务关闭时，会停止新的 HTTP 请求并请求取消正在运行的 Workflow、Job 和外部通道处理。启动时会检查遗留的未完成运行，将其标记为中断，以便后续排查和重新执行。

## 边界与取舍

- Hephaestus 面向单个受信任使用者，不是多租户协作平台。
- 平台提供聊天历史检索，不依赖向量数据库。
- 历史分支和运行记录优先保留，以支持回看、调试和重新选择路径。
- 工作流以自然语言步骤为中心，适合可解释的个人自动化，而不是替代通用编排系统。
- 文件、Shell、网页获取和外部通道都可能接触外部系统；启用这些能力前，应结合个人部署环境评估风险。
